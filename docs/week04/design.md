## 文案风格约定（实现代理必读）

本节约定出自写作风格 skill（`write-lesson-plan`），幻灯片正文与演讲者备注都遵守。

1. **正向表述优先。** 避免"不等于""不把 X 当成 Y"式的一句话负向表述。拿不准的表达用"可能""在 XX 情况下"等限定词；需要概念辨析时，在合适位置直接写一个完整段落，交代两个相近概念各自的背景、区别与关联，而不是用否定句点一下。
2. **恰当使用引言。** 名人已经说透的内容照抄原文并注出处，用引言加强印象；本讲引文（阮冈纳赞五定律、FRBR 四层、Dublin Core source、Plan 9 三原则、开闭原则、RDF 三元组、SKOS prefLabel/altLabel/scopeNote 与 changeNote/historyNote、FAIR R1.2、阿伦斯、卢曼、Svenonius 受控词汇）一律按教案原文照抄，含原文语言与出处行。
3. **注重归纳。** 多个实例并列呈现之后，用一两句把共同结论收出来（如四工具对照后归纳"一等对象决定工具形态"），不要让材料停在罗列。
4. **后页依赖前页。** 每个概念首次出现即给定义或案例，后文直接使用；幻灯片之间保持引入—展开—回收的次序。本稿在每页"机制背景"里标明该页机制被哪些后页复用。
5. **备注三段式。** 每页 notes 只写三段：目的（破除什么误区）／范例引导话术（讲师如何引导学生看交互）／机制背景（公式或工程含义，不复述页面文字）。
6. **页脚一句来源/模式说明。** 每页页脚固定一句，交代来源与运行模式（示例："D12 · CSL 渲染：Fsharp.Citeproc WASM 实时；题录来自本机 patchouli 库导出"）。

### D01 导言：找得到 · 辨得清 · 引得准

- **标题**：一个古老问题的新形态
- **kicker**：D01 / 导言
- **正文要点与文案草稿**：学术阅读本质上做三件事，写成三栏卡片：①**发现**——从无限的书中筛出少数能用的书，第一道门槛不是理解，而是找到该读的；②**判断**——把读到的内容作为论证依据前，持续回答版本可靠吗、作者是谁、在学术谱系中处于什么位置；③**对话**——写作征引前人之说，要追得出这本书从哪来、经历了什么、此刻是否仍如其原貌。三栏底缘各钉一枚递进箭头：找得到 → 辨得清 → 引得准。其下两行"数字重演"：搜索引擎服务找得到；同行评议与引用指标服务辨得清；DOI、版本控制与引文规范服务引得准——目录学没有消亡，只是从纸面搬进了检索系统。段末一句：AI 改变了这条链上各环节的成本结构，却没有取消任何一环。页尾预告三种记录：关于材料的记录、关于理解的记录、关于关系的记录——本讲各章分别处理它们的建立、组织与维护。
- **交互说明**：三栏卡片点击展开"古代形态 → 数字形态"两行对照（导言段落的压缩）；展开顺序自由，不影响后页。
- **演讲者备注草稿**：目的：破除"AI 时代找书已经解决、组织工作无关紧要"的预期，让学生带着"成本结构变了、责任没有消失"的视角进入全讲。引导话术："先想一个你自己的文献库：最近一次打开其中一份 PDF，你能说出它是哪个版本、从哪个渠道取得的吗？三秒钟答得出的请举手。"机制背景：三重需求是本讲的骨架，D02 给它的两千年史料、D03 给它的八条原则；三种记录是 D05（材料）、D20（理解）、D22（关系）三页的前置概念，此处首次点名。
- **运行模式**：静态内容
- **方案A/B**：A＝三栏卡片，点击展开；B＝一条横向链条图随讲述逐步点亮。选 A：三栏与"三种记录"同构，D29 结语可按同一构图回收。

### D02 目录学时间线

- **标题**：找书、辨书、引书：两千年的基础设施
- **kicker**：D02 / 导言
- **正文要点与文案草稿**：横向时间线 8 个节点，每节点一行事实（照教案）：①约前240年，卡利马科斯在亚历山大图书馆编成一百二十卷《表》（Pinakes），按学科分类、类内按字母排序、附作者小传——西方目录学的滥觞；②西汉，刘向、刘歆父子受诏整理群书，广罗异本、校雠文字，"条其篇目，撮其旨意"，叙录"论其指归，辨其讹谬"；③约987年，伊本·纳迪姆在巴格达编成《群书索引》（Fihrist），刻意区分"亲见之本"与"耳闻之本"，以卷数、页数与抄本异同鉴别伪托；④1841年，帕尼齐为大英博物馆图书馆编写 91 条编目规则，目标是让目录聚合同类、区分相似；⑤1876年，卡特在《印刷本字典式目录规则》中写下目录的两个目标：使读者能够找到一本文献，并使读者能够看到图书馆拥有哪些相关文献；⑥1931年，阮冈纳赞《图书馆学五定律》把"用"确立为组织工作的最终裁判；⑦1998年，FRBR 用实体–关系模型重新描述书目世界；⑧2016年，Wilkinson 等人提出 FAIR 原则，把可发现、可访问、可互操作、可重用写成数据管理的高层框架。时间线下方引言条：唐代毋煩形容目录的用处是"不见古人之面，而见古人之心"。页脚归纳一句：各文明进入这条链的端点不同——中国从校雠反向走到目录，希腊从图书馆编目出发，伊斯兰世界从书商目录走向联合书目——需求是共同的，先被卡住的环节不同。
- **交互说明**：横向滚动时间线；节点按三重需求分色（找得到／辨得清／引得准）；点击节点弹出两行细节卡（事实出处＋被哪重需求塑形）。
- **演讲者备注草稿**：目的：破除"组织技术是检索系统时代的新发明"的错觉，建立"需求塑形技术"的因果视角。引导话术："请在这条线上找一找：哪些节点主要被'找书'塑形？如果给刘向父子一个今天的文献管理器，他们第一个会要求的功能是什么？"机制背景：时间线为 D03 八原则提供历史出处——每条原则都能在线上找到先声；D15（Lubetzky）、D16（冒号分类法）会回到这条线取史实。
- **运行模式**：静态内容
- **方案A/B**：A＝横向时间线＋需求分色；B＝三行泳道（三种需求各一行，事件入对应泳道）。选 A：泳道会切断"殊途同归"的观感，时间线强调需求如何接力塑形技术。
- **页脚**：D02 · 史实与引文出自教案导言及参考阅读（Blair 2010；姚名达；章学诚；Ibn al-Nadim 1970）。

### D03 八原则总览

- **标题**：组织知识系统的八条原则
- **kicker**：D03 / 导言
- **正文要点与文案草稿**：8 卡网格，每卡：原则名＋一句检验问句（问句取自附录二检查表）＋展开章次。1 用户导向（以用为纲）——每个字段、标签与记录动作能否回答"这帮助谁找到什么、支持什么判断"？（导言）2 内容与载体分离——同一著作的多个版本与副本能否分别指认、分别清理？（1.4）3 实体–关系导向——重要关系是否显式记录并带类型与理由？（5.2）4 词汇控制——同一概念是否只用一个首选名称，异称可查？（6.3）5 标准化与互操作——核心字段是否贴合共享语义，对象是否有持久标识符？（1.6）6 充分且必要且简约——记录是否恰好完成功能，每个装置只担一职？（1.2、2.2）7 可演化的动态结构——新类型、新主题能否不改核心就纳入？（2.3）8 可追溯与可信任——每条重要记录能否说清从哪来、何时改过、现在还能不能用？（7.2）卡区下方五定律引文块（照教案原文）：

> Books are for use.（书是为了用的。）
> Every reader his book.（每个读者有其书。）
> Every book its reader.（每本书有其读者。）
> Save the time of the reader.（节省读者的时间。）
> A library is a growing organism.（图书馆是生长中的有机体。）
> ——Ranganathan, *The Five Laws of Library Science*, 1931

  引文下两句：第一条裁判其余七条的取舍；在个人系统里，读者首先就是未来的自己。再补一行 Svenonius："用户便利"为书目描述第一条原则，其下"遵从通行用法"——描述沿用使用者习惯的称谓，而不是编制者自以为更正确的称谓。

- **演讲者备注草稿**：目的：把八原则从"要背的清单"转成"可反复使用的取舍裁判"，每条原则配一句将来能直接自问的话。引导话术："八条不要求现在记住。请只盯住第一条——以后任何一条拿不准，回到'这帮助谁找到什么'。"机制背景：八原则是全讲的评价语法，D28 六方面验收与课后发放的附录二检查表都由它导出；卡上的章次标注构成全讲导航索引。
- **运行模式**：静态内容
- **方案A/B**：A＝8 卡网格＋点击跳章；B＝单列表格逐条配例子缩略。选 A：总览要一眼尽收，网格密度符合本课件 Swiss 风格。

### D11 1.5 字段语义

- **标题**：字段语义：同名栏目的不同含义
- **kicker**：D11 / 教案 1.5
- **正文要点与文案草稿**：正文三段。其一：材料从网站进入管理器，又从管理器导出到表格或笔记，字段名称和含义可能变化；字段映射就是说明原记录中的信息进入新记录的哪个位置，以及含义是否保持一致——它不是把一列换个名字，日期指什么时间、来源指什么关系，都影响后来能否准确使用。其二：Dublin Core 提供通用元数据术语，帮助思考标识、日期与关系的差别；其 source 的定义是引文块（照教案原文）：

> "A related resource from which the described resource is derived."
> （所描述资源由其派生而来的相关资源。）
> ——DCMI Metadata Terms

  其三：source 指母体或来源资源，比日常所说的"引用出处"含义更宽，因而迁移时不能机械对应到任何软件里名为"来源"的栏目；标准的作用是帮助约定语义，不是要求每种史料填满同一张表。

- **演讲者备注草稿**：目的：破除"列名相同＝含义相同"的迁移假设，为 D12 标准化链备好问题动机。引导话术："这个网站把'来源'填成期刊名；导出到另一个工具后，这个词还可能指数据库、馆藏机构或母文献——迁移之前，先问这个栏目在原系统里回答什么问题。"机制背景：字段映射是跨系统一致性的最小契约；DC 术语给出共享语义层，"含义是否保持一致"由此成为可讨论、可核对的问题。

### D13 1.6 标识符与 Plan 9 名字空间 + live URI 解析

- **标题**：标识符与名字空间：身份与组织分离
- **kicker**：D13 / 教案 1.6
- **正文要点与文案草稿**：正文四段。其一：目录学困境有个技术根源——书无限增长，任何分类位置与著录款目都会被后来者挤占、修订；把一册书的身份寄托在分类号或架位上，身份就会随每次类目调整而迁移；计算机时代的回答是给每个对象一个不随位置与分类变化的标识符，把身份与位置解耦——分类可以改，文件可以搬，身份不变；DOI、ISBN、ORCID 乃至任意 URI 都是这一回答的不同形态。其二：标识符具有双重性质——它是文献身份，使任何记录都能回查到同一对象；它也是一种组织形式——超链接建立在标识符之上，题录、笔记、页级文本、译文这些异构对象共享同一套标识，就能被链接整合进同一个知识系统。其三：Plan 9 引文块（照教案原文）：

> （1）一切皆文件：所有资源以文件接口呈现；
> （2）统一协议：本地与远程资源经同一协议（9P）访问；
> （3）私有名字空间：每个进程可以用 bind 与 mount 装配自己的资源视图。
> ——MIT PDOS 6.828 课程讲义对 Plan 9 设计原则的概括（中译）

  其四：启示——组织视图与对象身份可以分离：同一批对象在不同名字空间下呈现给不同使用者，对象本身不必移动；这与目录学"身份不随分类位置迁移"是同一个思想——名字空间是可塑的组织层，标识符是稳定的身份层。patchouli 的对应：通过 MCP 接口向 AI 暴露只读虚拟文件系统，库中对象以 `patchouli://` 方案的 URI 寻址，根下分设 items、texts、translations、csl-styles 等入口；这些 URI 可以经解析反向定位回具体的页码，乃至页内的某一个文本块——标识符同时就是引用定位。

### D15 2.2 简约原则

- **标题**：简约：一个装置只承担一种功能
- **kicker**：D15 / 教案 2.2
- **正文要点与文案草稿**：正文四段。其一：主题与状态需要分开，背后是第六条原则的另一半——简约；Svenonius 提出配套设计原则：避免让一个组织装置兼任多种功能；她举的例子是同一标识兼用于消歧与排序——一物多用在技术变迁时会成为死结，因为两类需求各自演化，捆绑在一起就无法单独调整。其二：编目史的同构教训——分类号同时充当排架号与检索工具：排架要求每个复本只有一个位置，检索希望一个主题能从多个角度进入，一套号码难以同时服侍两个主人。其三：个人库里，"待读"是一个会过期的状态，"蒙古史"是一个长期有效的主题；两者混在同一标签云里，库越大，筛选越不可靠。其四：Lubetzky 1953——受美国图书馆协会委托检讨 1949 年编目规则，批评它是历年个案条款累积拼凑的产物，为同一情形设置了重复、重叠甚至冲突的规定；他主张回到目录的统一目标，用少量明确的原则重构规则体系；这份《编目规则与原则》成为 1961 年巴黎国际编目原则会议《原则声明》的思想基础。收束句：规则膨胀的教训对个人系统同样有效——整理规则每增加一条，都问它服务哪个既定用途、能否用已有规则推出；一个只有三条约定但始终执行的系统，胜过一个有三十条约定而无人记得的系统。
- **交互说明**："一物二用"演示器（教学构造）：一个标签同时承担筛选与排序，拖动"需求变化"滑块（新主题涌入／阅读进度推进），捆绑项连锁失效；对照面板展示拆分后两个装置各自独立演化。
- **演讲者备注草稿**：目的：破除"合并功能＝省事"；展示一物多用在技术变迁时成为死结的机制。引导话术："给这个标签改名，排序和筛选哪一处先坏？先坏的那处，就是被你捆绑的需求。"机制背景：职责单一使各部分可独立演化，与 D16 开闭原则互补——开闭管结构扩展，简约管装置职责；Lubetzky 给"原则统摄规则"提供历史先例，也为 D28"规则能否用已有约定推出"的取舍埋点。
- **运行模式**：教学构造（演示器为前端构造场景；引文与史实为静态内容）
- **方案A/B**：A＝滑块演示连锁失效；B＝1953／1961 史实＋个人库类比的双时间线。选 A：机制要亲手拖过才看得见。

### D16 2.3 可演化结构

- **标题**：可演化的动态结构
- **kicker**：D16 / 教案 2.3
- **正文要点与文案草稿**：正文四段。其一：阮冈纳赞五定律第五条"图书馆是生长中的有机体"，正是第七条原则的先声；他设计的冒号分类法（首版 1933）开创分面路线——与预先罗列全部主题的枚举式分类不同，分面分类把主题分析为若干基本范畴，再按需合成类号；新主题出现时可以即时组合，无须修订整张类目表。其二：知识组织的标准论断——枚举式体系难以容纳尚未预见的知识，而分面体系具有"好客性"（hospitality）；SKOS 把同样的谨慎写进规范自述：对一个形式约束是否纳入存疑时，宁可不纳入，以防"过度承诺"，这与 Gruber 的"最小本体承诺"一脉相承。其三：个人系统的对应做法——初次取得材料时不知道其全部用途是正常状态；有效的组织应当容纳暂定归类，也允许删除不再有用的标签；没有必要先设计覆盖整个学科的分类树，再允许自己开始阅读。其四：开闭原则引文块（照教案原文）：

> "A software artifact should be open for extension but closed for modification."
> （软件制品应当对扩展开放，对修改关闭。）
> ——Bertrand Meyer, *Object-Oriented Software Construction*, 1988, p. 23

  三工具对应：JabRef 纯文本库可直接在条目里加自定义字段，Zotero 的 extra 字段长期承担标准字段之外的寄放，patchouli 题录在核心字段之外留有开放扩展位——三家做法不一，方向相同：核心尽量稳定，扩展尽量自由；开放扩展的代价（词表失控）留给第六章。

- **演讲者备注草稿**：目的：破除"先设计完美分类树再开始阅读"；把可演化从工作感觉提升为结构性质。引导话术："你的研究明年转向一个新主题——这张类目表要动几处？分面合成器里，新主题只是一个新取值。"机制背景：分面＝独立维度的组合空间，好客性即组合空间对未预见取值的开放；SKOS 的"不过度承诺"是语义层的同一谨慎，开闭原则是工程层的同一准则。
- **运行模式**：教学构造（合成器为前端真实算法；引文与史实为静态内容）
- **方案A/B**：A＝分面合成器＋枚举树对照；B＝SKOS 约束取舍案例卡。选 A：演化的代价差异只有亲手操作过枚举树才具体。

- **正文要点与文案草稿**：四个动作各一段。**①让输入范围服从阅读任务**：只有题录或摘要，可以判断暂定阅读顺序；解释难句需要相邻语境；梳理整篇论证应检查问题、证据与结论所在部分；跨文献比较须分别保留各篇输入范围；检索返回的片段提示精读位置，范围不足时补充材料和阅读，而不是继续要求输出更完整的总结。篇数分层一句：二手研究的篇数是载体层的数量，出处依赖关系属于内容层——三篇论文转述同一档案，论证的支持仍然只有一份。**②把核验的增量写回来源笔记**：第二周的四层核验沿用，本讲处理核验之后的保存——究竟核清了哪一点，哪些判断被收窄，哪些部分仍有缺口；笔记让作者表述、自己的释义、自己的推断和机器建议保持可辨认；引文保留原话与位置，释义保留论述归属，个人推断说明从哪些依据走到了哪一步；核验结束后，应保留下经过判断的关系。**③阅读没有结束时保存继续的起点**：把已有理解、待回读位置和缺失材料区别开来——需要全文的进入获取队列，需要补上下文的保留位置，需要比较另一种解释的进入问题索引；状态的变化对应实际进展，记录未完成状态能减少反复重新进入同一材料的成本。**④输出可靠与自己理解是两项并行要求**：自我监控理解指辨认自己知道什么、为何这样理解、哪里仍不能判断；熟悉感与流畅感都可能使人高估理解，对话次数和提示词长度不能代替判断；读前留下问题和已有理解，读后再用自己的表达重述论证关系与限制。证据边界段（照教案）：Fu 等关于大学生 AI 阅读的观察，以及 Kreijkes 等关于 LLM 与笔记条件的实验，提供了关注加工过程的理由；两项研究的设计、对象与材料不同，不能直接外推到本课程研究生或当前模型；本讲保留自主重述与反思，是据此作出的教学安排，不是宣称某一流程已在本课堂被证明最优。

### D21 4.2 卢曼卡片盒四机制

- **标题**：卢曼卡片盒的四个机制
- **kicker**：D21 / 教案 4.2
- **正文要点与文案草稿**：上段实物研究（Schmidt 2018，基于比勒菲尔德大学所藏卢曼遗产）：系统由约九万张 A6 手写卡片组成，分前后两个卡片盒，运转依靠四个相互配合的机制。四机制卡：**固定地址**——每张卡片一旦编号便永不改号，分支式编号（如 17/11e）允许新卡插入任意两张旧卡之间，既有秩序不被打破，新内容无限加入，这实际上是"对扩展开放、对修改关闭"的纸质形态；**按未来相关性存放**——归档新卡时问的是"以后在哪些语境下我会想再次遇到它"，存放位置成为对将来使用场景的一次预判；**选择性引用**——卡片间引用指向具体卡片编号，是有意建立的连接，而不是系统化的全量互连；**稀疏的关键词索引**——索引只收录数千个词条，为数万张卡片提供少量入口，索引的职责止于"从哪里进入"，进入之后的漫游交给卡片间的引用。卢曼引文块（照教案原文）：

> "Ohne zu schreiben, kann man nicht denken."
> （不写下来，就无法思考。）
> ——Niklas Luhmann, "Kommunikation mit Zettelkästen"

  引文下一段：卢曼把卡片盒称为自己的"沟通伙伴"——写入与取用之间隔着漫长的时间，检索时遇到的是自己早已忘记的记录，系统于是给出连作者都未曾预料的组合与意外，Schmidt 把这种机制称为"意外的制造"。纠偏段：实物研究显示卢曼的实际使用远比传说凌乱，有效性来自机制的组合加上数十年如一日的日常使用；可迁移的教训在机制层面——固定地址意味着可返回性（呼应 1.6 标识符），稀疏而有意的入口防止索引膨胀（词汇控制在笔记层的对应物），选择性引用意味着链接要带理由（第五章展开），插入式编号意味着结构向未来开放；日记式研究记录、按文献的长笔记和按问题的短笔记都可以实现这些机制。
- **交互说明**：左侧为可操作的3D木质卡片盒，内置六张以问题为题的Markdown卡片。取卡与放回呈现纸卡移动；新卡可书写、选择精确文档出处并说明引用理由，放入盒中保存，取消时焚毁丢弃。右侧保留卡片与关联展开示意图，固定地址、选择性引用、明确理由分别高亮当前卡的稳定URI、问题标题、引用理由；意外关联不触发操作。点击出处进入同区域的PDF阅读，返回仍是原卡。
- **演讲者备注草稿**：目的：让学生在取出、书写与放回纸卡的体验中理解固定地址、问题导向和引用理由。引导话术："取出一张卡，看看问题、材料与理由怎样相连；再新建一张卡，它加入后，旧卡的地址有变化吗？"机制背景：每张卡使用固定的patchouli://notes/{uuid}.md地址，文档引用钉住PDF页序、rev修订与box文本块；新卡在浏览器单独保存，导出为Markdown，不写入SQLite。
- **运行模式**：浏览器交互；CSS 3D动画；独立Markdown卡片；预置正文VFS引用。
- **方案A/B**：按教师明确选择采用3D卡片盒及示意图荧光高亮。
- **页脚**：D21 · 取出、书写与放回卡片；点击示意图高亮对应内容。

### D22 5.1—5.2/演示6 三层链接 + RDF 三元组 + 关系光谱 + live 引用解析

- **标题**：链接的三层与关系的光谱
- **kicker**：D22 / 教案 5.1—5.2 · 演示6
- **正文要点与文案草稿**：上段三层链接（照教案）：批注的回页链接指向文件位置；文献条目的相关连接指向另一条记录；问题笔记中的关系说明解释两个判断为什么应当一起讨论。三层可以连接，各自保存不同信息——返回原页，有机会阅读上下文；把两份文献放在一起，有机会比较；说明它们相同、相异或相互限制在哪里，才开始保存研究判断。段末一句：材料相互引用、使用相似词语与存在思想影响，是不同的论断。中段 RDF 引文块（照教案原文）：

> "The core structure of the abstract syntax is a set of triples, each consisting of a subject, a predicate and an object."
> （抽象语法的核心结构是一组三元组，每个三元组由主语、谓语和宾语构成。）
> ——*RDF 1.1 Concepts and Abstract Syntax*, W3C, 2014

  引文下谓语段："这条笔记引用了那本书""那本书是这条史料的一个版本""两位作者是同一人"是三种谓语，各自允许不同的推断；把它们都画成图谱上无差别的连线，等于把谓语丢掉只留主语宾语——这正是许多"知识图谱"视图看起来热闹却难以支持判断的原因；个人笔记系统不必引入 RDF 全套装备，但应守住最低形态：重要的关系有明确的类型和理由，能从关系的一端走到另一端。下段关系光谱：Zotero 的"相关条目"能记录两条文献有关，关系的性质留给使用者自己记；JabRef 条目里的 crossref 等交叉引用字段带有 biblatex 规范给出的语义；patchouli 的引用解析只依据持久化的文档—题录关系，从一页识别文本回到所属题录，走的是数据库里保存的关系指针——宁可承认"不知道这页属于哪条题录"，也不用字符串去猜。收束句：关系可以是笔记里的一句话、有规范语义的字段，或是系统拒绝猜测的硬约束；越往后，关系越能被机器忠实地搬运，也越要求建立时就说清它是什么关系；猜错了的关系比没有的关系更难清理——它会把错误安静地传播给每一次引用。
- **交互说明**：live 引用解析：对一页识别文本执行"它属于哪条题录"的解析，展示只走持久化关系指针；对照组演示"按标题相似度猜"如何把相似标题的另一本文献错挂过来（失败可见）。光谱三档与三层链接为静态区。
- **演讲者备注草稿**：目的：破除"连线＝关系成立"与"图谱越密组织越好"；把关系类型与理由确立为记录的最低形态。引导话术："这条边允许你作什么推断？答不上来，就是谓语还没写。现在看 patchouli 的答案：它宁可说不知道，也不替你把标题相像当成同一条。"机制背景：三元组是关系的一等公民化；持久化关系指针与字符串匹配的判别准则；光谱三档对应"建立时是否已说清关系"的成本差异。
- **运行模式**：浏览器实时（解析与对照演示在种子库真实执行）＋静态引文区
- **方案A/B**：A＝光谱三档＋live 解析；B＝关系图大画布可视化。选 A：画布展示"热闹"却掩盖谓语，恰是本页要破除的。
- **页脚**：D22 · RDF 引文照教案（W3C 2014）；解析演示走 patchouli 持久化关系。

### D23 5.3—5.5 反向链接 / 未链接提及 / 问题索引 / 证据矩阵

- **标题**：入口、问题索引与证据矩阵的接续
- **kicker**：D23 / 教案 5.3—5.5
- **正文要点与文案草稿**：上段反向链接与未链接提及：内部链接从一条笔记指向另一条，反向链接列出哪些笔记指向当前笔记，二者使进入同一记录的方向更多；未链接提及只是名称出现的候选，还须判断是否指同一对象、是否与当前问题有关；全文搜索适合找记得的词句，有理由的链接保存当时为何把内容联系起来。中段问题索引：围绕一个问题汇集已有判断、支持材料、可能反例和未决部分的导航记录，可以持续改写；它不是完整的知识树，也不要求把一切阅读都放入同一分类系统——索引随问题生长，结构为问题服务（可演化原则在笔记层的形态）。比较一句：比较首先要求范围可比，材料时期、文本类型、概念用法和证据基础不同，可能解释表面上的分歧；几篇研究共同依赖一个原始出处时，应记录这种关系，避免将重复转述误计为独立支持。运动方向一句：向下返回来源和位置，便于检查依据；横向与向上组织理解、限制和反例，便于发展问题。下段证据矩阵（衔接第三周）：第三周的证据矩阵已经整理陈述、依据、限制与缺口；本讲把它与问题索引连接——让来源栏能够返回文献与原文位置，让下一步能够指向待读材料，并保留当时的纳入范围；补证时既加入新材料，也修改比较理由；问题改变以后可以重新组织既有笔记，旧矩阵的结论则须经过检查再进入新问题；前沿研究对主张与证据绑定的探索（Pan et al. 2026）可供教师比较，但不改变本节重点：使文献记录、来源笔记和问题索引能够彼此返回。

- **方案A/B**：A＝问题索引活页＋反向链接侧栏；B＝矩阵与索引双栏对照。选 A：索引是操作对象，矩阵在来源栏被召回即可。

### D25 6.3/演示7 词汇控制 SKOS

- **标题**：词汇控制：SKOS 与个人词表病灶
- **kicker**：D25 / 教案 6.3 · 演示7
- **正文要点与文案草稿**：上段 Svenonius 引文块（照教案原文）：

> "the sine qua non of information organization"
> （信息组织的必要条件。）
> ——Svenonius, *The Intellectual Foundation of Information Organization*, 2000, p. 89

  引文下配方段：没有词汇控制，同一概念在记录中以各种面目出现，汇集——把关于同一对象的所有记录带到一起——就成为碰运气；经典配方是同一概念用唯一、稳定的标识与首选名称，同义异称归并到首选名称之下，概念配上说明用法边界的注释；W3C 的 SKOS（2009）把配方标准化为引文块（照教案原文）：

> prefLabel："The preferred lexical label for a resource, in a given language."（首选标签：一种语言下每个概念至多一个。）
> altLabel："An alternative lexical label for a resource."（交替标签：归并同义异称。）
> scopeNote："A note that helps to clarify the meaning and/or the use of a concept."（范围注释：说明概念的含义或用法边界。）
> ——*SKOS Simple Knowledge Organization System Reference*, W3C, 2009

  （ISO 25964 两部分 2011／2013 规定叙词表编制与互操作规范。）中段病灶与药（归纳表）：真实个人词表的典型病灶各有一味药——同一概念的大小写变体各自挂材料，检索其一其余沉默 → 变体归并为 altLabel；多套分类体系的类号与自由主题词同处一栏 → 分类号归入各自的体系字段；书目数据库导入的规范标目与随手自由词混排 → 规范标目与自由词分层存放；导入时的关键词未经清洗 → 清洗后再进词表。工具一句：Zotero 区分自动与手动标签，JabRef 关键词是条目字段、群组另成体系，patchouli 标签只做空格修剪与大小写敏感去重、改名即归并——三家都提供词汇的最小骨架，也都没有内置首选名称、交替标签与用法说明的位置；骨架能做归并动作，归并的依据替使用者回答不了。下段历史分寸："太平天国""洪杨之乱""粤匪"指涉同一对象，却分别携带立场的痕迹；把它们全部改写为首选名称，等于销毁用词差异中包含的历史信息；正确的做法是 SKOS 式的归并而非替换——检索时异称把人带到首选名称之下，原文中的用词则原样保留；scopeNote 在这里派上用场，写明本词表在何种意义上把这些异称视为同一概念；历史对象的同一性判断（两位同名作者是否一人、两个年号纪年是否一事）超出词表层，应留下判定依据，交由研究本身解决。
- **交互说明**：左：病灶→药归纳表（静态）。中：live 标签实验台——演示7①制造一对仅大小写不同的标签，检索其一，另一个沉默；演示7②把一标签改成已存在的名字完成合并，被吞掉的写法从历史记录找回。右：词表记录卡——为"太平天国"写 SKOS 记录（演示7③）：prefLabel＝太平天国，altLabel＝洪杨之乱、粤匪，scopeNote＝本词表在指涉 1851—1864 年起事政权这一对象的意义上视三者为同一概念；三字段可编辑，实时生成规范记录。

### D26 7.2/演示8① 可追溯四点解剖 + live OCR 修订链

- **标题**：可追溯的四个工程承诺
- **kicker**：D26 / 教案 7.2 · 演示8①
- **正文要点与文案草稿**：上段 FAIR 引文块（照教案原文）：

> "R1.2. (Meta)data are associated with detailed provenance."
> （（元）数据应附有详细的来源信息。）
> ——Wilkinson et al., "The FAIR Guiding Principles", 2016

  引文下两句：没有来源的数据无法被复用，也无法被治理；常被混淆的"符合领域社区标准"是 R1.3。SKOS 词表注释引文块（照教案原文）：

> changeNote："A note about a modification to a concept."（修改注释：记录一次改动。）
> historyNote："A note about the past state/use/meaning of a concept."（沿革注释：记录概念过去的状态、用法与含义。）
> ——*SKOS Reference*, W3C, 2009, §7

  校勘段：历史学者对这套思想并不陌生——校勘记的精神正在于此：底本是什么，何处据何本改字，异文如何处置，都要留下可以复查的痕迹；数字时代的可追溯原则，是校勘传统的工程化。中段四点解剖（patchouli 模型为例，认识论前提：受保护的是 OCR 文本树，题录是投影）：**不可变**——文字识别或人工校正提交的每一版页面文本都是一条不可变修订，数据库层面直接拒绝改写已提交的内容；**追加式**——撤销一次修改的方式是产生一条标记为"回滚"的新修订，历史链条永不倒退，正如史学界修订观点靠发表新论文，而不是收回旧刊涂改版面；**可指认**——全文检索的每个命中都携带"哪一页、哪一版修订、哪一个文本块"的完整定位，它就是 1.6 节那条可解析的 `patchouli://` URI，引用钉在它所指的那一版上，此后的校正不改动旧引用的解析结果；**诚实**——识别失败按失败保留，页面状态如实标注，等待在工作副本中校正后再作为新修订提交，而不是用一个看似整洁的结果掩盖识别失败。段末一句：这四条加在一起，恰好是"来源、版本、修改历史"三要素的完整落地。
- **交互说明**：四张解剖卡逐点开细节；live 修订时间线：对一页种子扫描件现场 OCR → 提交为新修订（时间线新增节点）→ 点击"尝试改写旧修订"→ 数据库触发器返回拒绝错误 → 旧引用 URI 与新引用 URI 并排解析对照（旧 URI → 旧文本；新 URI → 新文本）。OCR 引擎如实标注（见疑点记录）。
- **演讲者备注草稿**：目的：破除"可追溯＝能撤销"；追加式历史与覆盖式历史的差别，正是"撤回观点"与"发表新作"的差别。引导话术："撤销这次修改之后，时间线上少了什么？——什么都没少，多了一条'回滚'。史学界的观点修订也是这样发生的。"机制背景：不可变由数据库触发器在写入层拒绝改写执行；rev 定位使引用具备版本语义；失败按失败保留是诚实性与后续校正队列之间的接口。
- **运行模式**：浏览器实时（OCR、修订提交、触发器拒绝与 URI 解析在种子库真实执行）
- **方案A/B**：A＝时间线 live 链＋四卡解剖；B＝数据库触发器代码＋SQL 错误实录。选 A：课堂对象是机制而非代码；SQL 实录可进备注链接。
- **页脚**：D26 · 触发器与修订链为 patchouli 已核验机制；OCR 引擎以部署实录为准。

## 写作与实现疑点记录

1. **D26 OCR 引擎**：页表写"live RapidOCR 真跑一页种子扫描件"，但 `browser-port.md` 的受测浏览器基线是 Tesseract.js WASM（该文档明确"不冒称 RapidOCR／MinerU／NDL 的结果"），RapidOCR 的浏览器适配（ONNX Runtime Web）尚未验收。本稿把交互链设计为"现场 OCR → 新修订 → 触发器拒绝 → 旧引用仍解析旧版"，引擎写"以部署实录为准"。若实现时确认 RapidOCR 浏览器适配完成，须记录模型版本与散列后再改标引擎名。
2. **"题录投影可推倒重建"的表述边界**：教案 1.4／7.2 写"题录等其余数据是文本树的投影，可以推倒重建"；browser-port.md 记录该措辞与源码有出入——`ItemMetadata` 是持久用户知识，不能像 FTS 索引一样机械重建。D10 的 live 演示据此收窄为"重建检索索引等派生层，题录／笔记／标签保留"，请教案与工程两侧确认后统一口径。
3. **五定律第五条大小写**：教案正文作 "A library is a growing organism."，参考阅读注明 1931 年初版作 "A Library is a Growing Organism"。本稿引文照抄教案正文版；若课件需要初版措辞，以参考阅读为准并加注。
4. **D20"机器候选"成分**：教案演示5①写"标出原话、释义、推断与机器候选四种成分"，4.1 正文四成分是"作者表述、自己的释义、自己的推断和机器建议"。本稿按演示5①的四成分写练习，正文措辞按 4.1，实现时注意两种说法的对应。
5. **演示编号**：教案演示8含①证据引用解剖②删除阶梯③三种保存配置④find—fetch—cite 四节；页表把①给 D26（附 live OCR 链）、③④给 D27，删除阶梯②未列页。本稿按页表执行，若需覆盖②可在 D27 对照矩阵中加一行说明，不增页。
6. **外部链接**：教案所列 Fu et al. 2026、Kreijkes et al. 2026、Pan et al. 2026 等的链接与文献信息照抄教案原文，写作时未独立验证其可达性与版本；课件引用时保持教案口径。
7. **D30 四类划分**：词汇表四类为本稿拟定（教案无此内容），实现定稿时可按全讲实际用词调整词条归属，不改四类结构。
