## 每页的实际操作与观察点

|---|---|---|---|
| D00 | 这份材料如何进入下一次研究？ | 从已有书库进入检索、PDF导入和来源回查。 | 四份预置原件、题录与353页正文已经可用；之后的材料加入同一个库。 |
| D01 | 找得到、辨得清、引得准各需要什么记录？ | 为一个研究问题分别确定检索词、版本信息和引用位置。 | 检索词带回候选，文件身份区分副本，证据URI定位原话。 |
| D02 | 目录学的旧问题怎样进入今天的工具？ | 展开一个节点，比较它解决的需求与现代书库区域。 | 分类、辨版、著录与持久定位不断形成新的实现。 |
| D03 | 八原则如何检验同一套工具？ | 任选一条原则，跳到对应实际界面，完成一次操作。 | 每条原则都有可观察结果：身份、范围、关系、命名、交换或修订。 |

| D05 | 条目、字段、元数据与附件如何对应到同一条文献？ | 点击实体切换书库、编辑题录与文件关联；原件进入PDF工作台，退出回到上一界面。 | 题录、附件、阅读进度分别显示；未编辑字段与原有ID保留。 |

| D08 | 引用指向哪个副本、哪次文字修订？ | 查看文件哈希，打开同页的当前与历史URI。 | 题录年代、文件身份和正文提交时间是不同信息。 |
| D09 | 作品、表达、载体与单件各承担什么属性？ | 逐层展开WEMI，判断译者、版次、出版者和单件缺页的归属。 | 内容、版本与具体副本可以分别描述。 |
| D10 | 哪些是持久知识，哪些可以重新生成？ | 重建派生全文索引，对照重建前后题录、笔记、标签和修订数量。 | 检索条目与FTS可重建，原始材料与知识记录保持。 |
| D11 | 字段名相同，语义是否相同？ | 查看作者结构、出版信息与PDF取得位置，在笔记中区分出版来源和衍生来源。 | 题录、文件路径、来源记录分属于不同实体。 |
| D12 | 同一题录怎样形成可交换、可渲染的引文？ | 选择真实题录，切换课堂样式及locale，对照输出与CSL JSON。 | 同一结构数据进入Fsharp.Citeproc实时渲染。 |

## 同一套工具的持续使用

- 默认打开D04书库。工具菜单直接到实际操作页；课程页索引与讲解标注说明理念，关闭弹窗仍继续使用相同数据。
- D06多PDF导入，绑定当前题录或新建题录；全文逐页提取，原件按BLAKE3去重。空扫描页保存PDF而不提交假文字。D26选择页范围实际OCR、取消和续做；已处理页默认保留，显式选择重新处理才创建新修订。
- 右侧持续可核对原页与正文、复制固定修订URI、查看历史，并校对后提交新修订。
- 元数据、题录笔记、标签、集合成员、工作状态使用原表；研究记录、集合说明、关系理由、词汇约定、卡片和维护动作使用原生items.custom_fields_json中的x-pku-research扩展，不增加自定义表或改变schema。原桌面版本保留这些自定义字段记录，但没有相应网页研究表单；SQLite格式互读与桌面界面功能范围分别记录。
- D18可保存检索上下文、任务与未完成记录；真实API生成仍要求用户配置端点。API Key不进入数据库、记录或备份。
- ZIP备份同时带SQLite和PDF，实际打开备份可继续使用；SQLite单文件用于桌面打开，CSL JSON用于题录交换。
- 本地整站白名单包括三份哈希固定的ONNX模型，以便扫描PDF处理可运行。数据、PDF和模型仍不进入Git，未部署。

## 实现取舍

- 保留一个Library实现、一个PDF处理服务、一个工作台组件。旧三层实验UI和单页导入／OCR组件撤除，工程检查入口指向当前工作台。
- 本地处理逐页提交，完成部分遇到取消或失败仍保留；后续按现有修订续做。没有跨设备自动同步、后台任务在关闭浏览器后继续运行或自动从网络补全题录的声明。
- 文字层提取记为import，模型OCR记为ocr_adopted，人工校对记为manual_edit；出处和修订不会因讲解标注开关改变。
- 软件对账与实际PDF测试分别验收，不把讲解示意、模型置信度或题名相似度当作史实核验。

最新界面与逐页导航以[示意图与同一应用](diagram-navigation.md)为准；所有讲解标注按钮及弹出内容已经移除。
